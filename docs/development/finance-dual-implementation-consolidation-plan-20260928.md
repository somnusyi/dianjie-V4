# Finance 双实现归并方案（仅方案，不实施）

日期：2026-09-28

## 当前事实

- `/v2/finance/**` 有 19 个页面，面向现有移动端/通用 Finance Shell。
- `/v2/finance-pc/**` 有 30 个页面，除共同能力外还包含预算、成本核对、待开发票、工资、期末结账、税务、上游结算等 PC 专属页面。
- 两套路由在资金、发票、应付、付款申请、对账、门店、凭证和五类报表上重复实现；现在没有足够证据证明两边字段、权限和状态操作完全等价，不能直接删除任一套。

## 默认目标

- 以同一领域能力、同一 API 契约、同一权限判定为唯一实现来源。
- 桌面与手机差异由响应式视图或薄路由壳解决，不继续复制业务状态与请求逻辑。
- 在逐页字段和动作核验完成前，两套路由都保留；本批不迁移、不删除、不改权限。

## 分阶段顺序

1. 建立页面映射表：逐页记录两边筛选、表格字段、动作、API、角色和手机/桌面差异。
2. 先抽共享的查询模型、状态文案、金额格式、权限守卫和动作服务，不改变路由。
3. 从只读报表开始归并，再处理门店/发票/应付，最后处理付款、资金、凭证、期末结账等写操作。
4. 每归并一个能力，同时跑 Finance 角色权限、金额 Decimal、状态机、移动端和桌面端回归。
5. 旧路由先改为兼容重定向并保留一个发布周期；确认无访问与书签依赖后再删除源码。

## 验收与回滚

- 相同业务在两种视口下字段、筛选、金额、状态和动作结果一致。
- 写操作只有一套实现，幂等、权限和失败提示有自动化测试。
- 生产发布前提供旧/新路由访问统计和回滚映射；任一页面未核清则保持双路由，不做删除。
