## 0. TL;DR

瑶海店使用美团智能 POS 收银（一体化覆盖现金/微信/支付宝/团购券/第三方平台），dianjie V4 作为**第三方企业内部管理系统**只读拉取数据用于库存联动 + 经营报表可视化。

**核心选择**：
- 走「智能版 API」(`/rms/pos/api/v2/poi/orders/*` + `/rms/pos/api/v1/poi/reverse/orders/*`)
- **不走** 2026-05-13 那份 webhook 方案（业务模型不同：webhook 是商家被动接单方，我们这次是商家被动读数据方）
- 用 `business_id = 18`（餐饮系统-智能版，文档确认）

**架构两步**：
1. **采集层** `sync.ts`：cron 每小时拉两个接口，按页落 `MtOrder/MtOrderItem/MtOrderPayment/MtRefundOrder`，并把每次 HTTP 调用完整落 `MeituanApiCallLog`（带 traceId / requestBiz / responseRaw / errorSeverity）
2. **处理层** `processor.ts`：把待处理 `MtOrder` 增量写入 V4 现有 `RevenueRecord`（`source='meituan'`），客户手工录入数据被自动覆盖（用户要求）

**响应反馈机制**：admin 路由 `GET /api/admin/meituan/calls/:id/ticket-template` 输出**直接粘贴美团 TT 工单**的 markdown，4 字段（接口名 / 请求参数 / 响应结果 / 问题描述）一次齐备。

**进度阻塞**：客户当前 ISV 注册流程在审批中，**appKey/Secret/Token 未下发**。本设计承诺 95% 代码可在凭证就绪前完成（Mock 客户端 + fixture 测试），剩余 5% 是真实签名联调 + .env 切换。

## 1. 背景

### 1.1 业务现状

- 瑶海店收银台 = 美团智能 POS（**所有支付方式聚合**：现金、微信、支付宝、团购券、抖音外卖、keeta、饿了么...）
- dianjie V4 是另一套独立系统：管供应链 / 采购 / 报损 / 财务凭证
- 客户痛点：美团 POS 上的实时收银数据无法进入 V4，老板看 V4 dashboard 看不到瑶海店真实营收
- 采购/库存/BOM **全在 V4 这边管**，美团 POS 那边的 SCM+ 模块没用 → 智能版 API 里的 `foodConsumption / foodbom / realTimeWarehouseStockReport` 系列**全部空表，不调**

### 1.2 与 2026-05-13 webhook 方案的关系

- **方案不同**：那份是「到店餐饮 webhook」（被动接单 + push to V4），我们这份是「智能版 API 轮询」（V4 主动 pull）
- **凭证不同**：那份用「到店餐饮 ISV」appKey；本份用「智能收银三方应用」appKey/Secret —— **两个独立的美团应用**
- **schema 不冲突**：那份的 `MeituanRawMessage / RevenueTransaction` 没有落地 migration；本份新表前缀 `mt_*` 不重名
- **风险**：客户可能后续两份都做。届时 `RevenueRecord.source` 字段值需要分别处理（meituan-pos vs meituan-webhook 区分）—— 当前阶段 spec 只用 `'meituan'`，等真有冲突时再细分

### 1.3 接口选型依据

- 在线点 API（`foodmop/order/diancannew/*`）：vendor-driven，需要 push 菜谱到美团 + 实现回调 URL。**不适合**只读管理系统 → 已排除（详见对话探讨日志）
- 智能版 API（`rms/*`）：read-only 查询，前提是商家已用美团智能 POS。**完全匹配**瑶海店现状 → 选定

### 3.2 RevenueRecord 写入策略（不改 schema，靠 processor 应用层）

```ts
// processor.ts 关键逻辑
for (const mtOrder of pendingOrders) {
  // 没有解析到 V4 storeId 的订单跳过 + 标记，不写 RevenueRecord 避免脏数据
  if (!mtOrder.storeId) {
    await markProcessError(mtOrder.id, 'storeId 未解析（poiId 与 V4 Store 无映射），跳过 RevenueRecord 写入')
    continue
  }

  const newAmount = mtOrder.payed - sumOfRefundsInPayments  // 净收入（分）
  const delta = newAmount - mtOrder.processedAmount

  if (delta === 0) {
    await markProcessed(mtOrder.id)
    continue
  }

  const storeId = mtOrder.storeId  // 上面已守卫非空

  await prisma.$transaction(async (tx) => {
    const existing = await tx.revenueRecord.findUnique({
      where: { storeId_date: { storeId, date: mtOrder.businessTime } },
    })

    // 首次遇到 manual 记录：归零 + 改 source=meituan，旧值进 rawData.replacedManual
    if (existing && existing.source === 'manual') {
      await tx.revenueRecord.update({
        where: { id: existing.id },
        data: {
          amount: 0,
          source: 'meituan',
          rawData: {
            ...((existing.rawData as object) ?? {}),
            replacedManual: {
              previousAmount: Number(existing.amount),
              replacedAt: new Date().toISOString(),
              reason: 'auto-overwrite by meituan sync (manual entry deprecated)',
            },
          },
        },
      })
    }

    const yuanDelta = new Prisma.Decimal(delta).div(100)
    const record = await tx.revenueRecord.upsert({
      where: { storeId_date: { storeId, date: mtOrder.businessTime } },
      create: { storeId, date: mtOrder.businessTime, amount: yuanDelta, source: 'meituan' },
      update: { amount: { increment: yuanDelta }, source: 'meituan' },
    })

    await tx.mtOrder.update({
      where: { id: mtOrder.id },
      data: {
        processed: true,
        processedAt: new Date(),
        processedAmount: newAmount,
        revenueRecordId: record.id,
        processError: null,
      },
    })
  })
}
```

支持的 4 种场景：
| 场景 | 行为 |
|---|---|
| 当天首次同步（无任何记录） | create 一条 source='meituan'，amount = delta |
| 当天后续小时再同步 | update increment delta（source 已 meituan） |
| 初始 backfill（7 天）碰到旧 manual 记录 | 归零 + 改 source + 旧值进 rawData.replacedManual + 正常累加 |
| 部分退款使 newAmount 变小 | delta 为负，increment 负值 = 自动 decrement |

### 5.1 三组 cron（方案 Y 双轨 + 日对账）

| Cron | 频率 | 接口 | queryTimeType | 窗口 |
|---|---|---|---|---|
| **主路同步** | 每小时 | `instore/query` | **2**=结账时间 | 过去 **24h** 滚动 |
| **退单兜底** | 每小时（同 cron 串行） | `reverse/orders/search` | **1**=营业日（唯一选项） | 过去 **2 营业日** |
| **日对账** | 每天 04:00 | 两个接口 | **4**(instore) / **1**(reverse) | 昨天整营业日 |

### 5.2 cron 伪代码

```ts
async function runMeituanHourlySync() {
  const correlationId = createId()
  const now = new Date()

  // 1. 主路：店内订单（结账时间，过去 24h 滚动）
  const cursor = await getCursor('/rms/pos/api/v2/poi/orders/instore/query')
  const ROLLING_HOURS = 24
  const AUTO_CRON_MAX_LOOKBACK_DAYS = 30                   // 自动 cron 安全 cap
  const since = new Date(Math.max(
    now.getTime() - ROLLING_HOURS * 3600_000,
    cursor.lastSyncedAt?.getTime() ?? 0,
    now.getTime() - AUTO_CRON_MAX_LOOKBACK_DAYS * 24 * 3600_000,
  ))
  await syncInstoreOrders({
    correlationId, since, until: now,
    queryTimeType: 2,           // 结账时间
    statusList: undefined,      // 不传 = 全部状态
    sortField: 2, sort: 2,      // 按结账时间正序
  })

  // 2. 退单兜底：过去 2 营业日
  const refundSince = new Date(now.getTime() - 2 * 24 * 3600_000)
  await syncReverseOrders({
    correlationId, since: refundSince, until: now,
    queryTimeType: 1,           // 只支持 1（营业日）
    statusList: undefined,
  })

  // 3. 处理层（同 cron 跑串行）
  await processPendingOrders()
}

async function runMeituanDailyReconcile() {  // 04:00 触发
  const yesterday = dayjs().subtract(1, 'day').startOf('day')
  const yesterdayEnd = yesterday.endOf('day')
  await syncInstoreOrders({
    correlationId: createId(),
    since: yesterday.toDate(),
    until: yesterdayEnd.toDate(),
    queryTimeType: 4,           // 营业日期
    statusList: undefined,
  })
  await syncReverseOrders({
    correlationId: createId(),
    since: yesterday.toDate(),
    until: yesterdayEnd.toDate(),
    queryTimeType: 1,
    statusList: undefined,
  })

}

async function fetchInstoreOrders(p): Promise<InstoreOrderResp> {
  const biz = {
    orgId: env.MEITUAN_ORG_ID,
    req: {
      queryTimeType: p.queryTimeType,
      beginTime: p.since.getTime(),     // 毫秒（biz 里都是毫秒）
      endTime: p.until.getTime(),       // 毫秒
      pageNo: p.pageNo,
      pageSize: 50,                      // 上限 50
      sortField: p.sortField,
      sort: p.sort,
      // statusList 不传
    },
  }
  const publicParams: Record<string, string> = {
    developerId: env.MEITUAN_DEVELOPER_ID,
    businessId: '18',                                   // 智能版（文档已确认）
    charset: 'utf-8',
    version: '2',
    timestamp: String(Math.floor(Date.now() / 1000)),   // 秒（公共参数是秒）
    appAuthToken: await tokenStore.getActive(),
    biz: JSON.stringify(biz),                           // biz 是 jsonString，不能传对象
  }
  publicParams.sign = signMeituan(env.MEITUAN_APP_SECRET, publicParams)

  // ⚠️ POST body 必须 form-urlencoded，不能进 query
  const body = new URLSearchParams(publicParams).toString()
  const resp = await axios.post(
    `${env.MEITUAN_API_BASE}/rms/pos/api/v2/poi/orders/instore/query`,
    body,
    {
      headers: { 'Content-Type': 'application/x-www-form-urlencoded;charset=utf-8' },
      timeout: 5000,
    },
  )
  // 落 MeituanApiCallLog（成功/失败都落）→ 见 errors.ts callWithRetry
  return resp.data
}
```

### 5.4 关键约束（再次明确）

- `pageSize` 上限 50（来自 schema doc）
- `beginTime` / `endTime` 毫秒（biz 内）
- `timestamp` 秒（公共参数）
- `businessId` 写死 18
- POST 必须 body，不能 query
- 自动 cron 回拉 cap **30 天**（不是用户硬限，是 cron 的安全护栏）

### 8.3 签名实现（真代码）

```ts
// signature.ts
import * as crypto from 'crypto'

/**
 * 美团技术服务合作中心签名算法
 * Doc: https://developer.meituan.com/docs/biz/comm-dev-isv-sign-rule
 *
 * 步骤（已对照官方 PHP / Java / C# 实现验证）:
 *  1. 取除 sign 外所有非空 key-value
 *  2. key 字典序排序
 *  3. 拼成 "key1value1key2value2..." （无 = 无 &）
 *  4. 前置 signKey (= appSecret)
 *  5. SHA1 → hex 小写
 */
export function signMeituan(
  signKey: string,
  params: Record<string, string | undefined | null>,
): string {
  const keys = Object.keys(params).sort()
  let str = signKey
  for (const k of keys) {
    if (k === 'sign') continue
    const v = params[k]
    if (v == null || v === '') continue
    str += k + v
  }
  return crypto.createHash('sha1').update(str, 'utf8').digest('hex').toLowerCase()
}
```

### 9.1 错误处理三层

| 层 | 出错时做什么 |
|---|---|
| HTTP / 网络 | axios 5s 超时 → throw → 落 callLog (mode=transport-error) → P0 报 Sentry |
| 业务（OP_*） | 按 `errors.ts` 字典：retry='once' 当场重试 1 次；'backoff' 跳过本 cron 后续 page；'inspectData' 看子码；false 抛错 |
| 解析 / DB | parser 异常 → 单笔 catch + 落 `MtOrder.processError`，不中断其他订单；prisma 错误 → 事务回滚 + P0 |

cron tick 最外层 try-catch：未捕获错误 → Sentry P0 + cursor 不推进 + 下次 cron 重试。

3. manual revenue 路由还在（之前决定不删 `revenue.ts`），重新启用手工录入
