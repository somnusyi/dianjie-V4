# 操作体验修复批次 2（2026-09-28）

## 范围

- 收货单生成后自动开始验收并直接打开明细验收面板，减少重复查找和点击。
- 合同、采购单、采购退货、月度对账创建成功后提供明确下一步动作；合同可从成功提示直接确认启用。
- 总仓单条/批量入库成功横幅增加“查看单据”，通过 `docs?doc=<id>` 打开本次真实单据。
- 到货差异中的采购单和收货单继续使用当前页明细弹层，不强制切换页签。
- procurement 六类空态、单据审核空态、供应商发票空态补上上一步入口。

## 业务默认方向

- 收货单生成成功后，如果状态为草稿，立即调用既有“开始验收”状态迁移，再打开验收面板；不跳过确认入库或二次复核。
- 合同启用仍使用 `ConfirmSheet` 二次确认；这里只简化创建后的定位与下一步，不放宽合同权限或状态机。
- 入库成功链接使用后端返回的真实 `WarehouseDoc.id`，重放请求继续指向同一幂等单据。

## 独立审查修正

- 合同创建后不再把缺少供应商的精简响应当作完整详情，改为按真实 ID 重新加载合同列表后打开。
- 采购单创建后通过详情 API 加载供应商、仓库和明细，不直接渲染精简创建响应。
- 采购退货正确解包 `{ replayed, purchaseReturn }`，首次与幂等重放都使用真实退货单 ID。
- 到货差异页打开采购单/收货单明细时，详情面板在当前页签上方展示，不再强制跳走。
- 批量入库保留后端返回的真实单据 ID，成功横幅可直达本次单据。
- 收货重放按状态分流：`INSPECTING` 进入验收，`PENDING_REVIEW` 进入复核，`POSTED/REVERSED` 只读查看，不展示错误动作。
