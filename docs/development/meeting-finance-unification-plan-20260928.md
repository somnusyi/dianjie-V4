# 财务双实现归并方案（仅设计，未实施）

## 现状与范围

`/v2/finance` 与 `/v2/finance-pc` 同时存在应付、资金、凭证、审核、门店、付款申请、发票、对账和报表页面。PC另有预算、工资、备用金、期间结账、成本核对、上游对账等专属入口，且有独立登录/PWA scope。不能用目录替换或统一重定向假定两者功能相同。

本次只让旧 `/login` 使用既有 `routeForRole` 进入v2，并关闭四个v1孤儿路由。财务手机/PC入口、业务与权限保持既有规则。本方案不构成发布或归并授权。

## 建议实施顺序

1. 建立逐页功能矩阵：API、筛选、审核/付款状态机、权限、附件、打印、PC特有操作与移动操作。以实际接口及回归测试为证据，不按同名文件推定等价。
2. 优先提取只读查询、金额/日期口径、表单校验与状态标签到共享领域模块；页面壳、响应式布局、PWA登录保持独立。每迁一页对比请求参数、租户/门店范围、分页、金额、导出及错误提示。
3. 审核与付款提交改为共享命令层，保留服务端授权、Decimal、幂等与事务约束。以并发重复提交、角色越权、附件丢失、驳回再提交测试作为迁移门槛。
4. 对真实功能等价的双页面使用同一内容组件、两种布局；PC专属页面继续保留。业务验收后再提旧页面重定向和导航收口。

## 验证与回退

- 角色矩阵至少FINANCE、ADMIN、SUPER_ADMIN、无权角色及不同租户；验证列表、详情、审批、下载和深链，而非只验证导航隐藏。
- 手机390px与桌面1440px覆盖查询、明细、键盘输入、审核确认、返回保持筛选和打印；PC PWA冷启动/登录/续期不能跳出scope。
- 逐页独立提交、逐页验收；迁移期保留旧实现和入口映射，异常可回退该页组件引用。涉及schema/接口变更另立向前兼容迁移与回滚计划，不能借归并改账务口径。
- 完成后明确唯一领域实现与两套布局的归属，再删除未引用代码。禁止在本次UX任务中扩大为财务重构。
