## 必跑验证

- 正常、边界、失败、权限、租户隔离、并发与幂等。
- 库存和金额必须在事务内一致，失败不能部分过账。

- 页面逻辑不合理时，即使接口和自动测试通过也不能销号；必须经过 ZCode 的页面流程审查和用户本地验收。
- Prisma 变更只走向前兼容 migration；隔离数据库执行空库和升级验证。
- API/Web 聚焦测试、全量测试、TypeScript、生产构建和 `git diff --check`。

## 架构、安全与失败边界

- 数据所有者：普通订货、独立补货、配送、采购验收、库存台账、供应商档案/资质各自维护状态；只通过明确外键和服务投影关联，不互相改写历史单据。
- 依赖方向：页面 → 角色受限 API → 领域服务 → Prisma 事务；报表只读领域事实，不反向写业务数据。
- 补货和配送生成采用幂等键、行版本及事务；并发失败返回可重试冲突，不允许生成重复配送或部分过账。
- 成本和利润只读取冻结的出库台账；缺少成本时显示待补并把利润留空，不以当前商品价或 0 伪造。
- 资质文件只保存当前租户对象键和元数据；读取时按单据、门店和角色授权后短签。供应链角色不读取完整银行账号、税号等财务敏感字段。
- 新字段/表均使用可向前兼容迁移；旧客户端和历史记录必须仍可读取。应用回滚不能删除库存、财务、资格证明或审计历史。
- 权限、幂等、租户隔离、状态机和来源互斥均需架构/契约测试；禁止页面隐藏代替服务端授权。
- 权威源码目录是本工作树；`.next-meeting-*` 与 `node_modules.pre-restore-*` 是历史本地验证产物，不纳入源码、不改写、不清理。
