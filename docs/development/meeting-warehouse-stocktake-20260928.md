# 总仓多人盘点供应链化开发记录

日期：2026-09-28

批次：四场会议修复批次 4（U-2）

状态：本地实现与自动化验证完成，未部署生产或 UAT

## 业务范围

- 新增独立的总仓盘点流程，不复用门店月度盘点 `InventoryCount`，门店既有盘点、报损和订货语义保持不变。
- 完整路径为：供应链员工创建盘点单 → 按分区分配盘点人员 → 各负责人逐人保存并提交 → 汇总提交 → 审核或退回。
- 审核通过后只按盘点差额生成盘盈单、盘亏单并过账；零差异不产生调整单或库存流水。
- 不提供反审核接口、按钮或状态；已确认盘点为终态。
- 普通供应链页面不再提供绕过审核的单 SKU 实盘按钮，改为进入“总仓多人盘点”。底层直接实盘能力仍保留给期初建账或管理员修复，不作为日常入口。

## 状态与权限

- 主单状态：`DRAFT → COUNTING → REVIEWING → CONFIRMED`；草稿或盘点中可取消为 `CANCELLED`。
- 分区状态：`OPEN → SUBMITTED`；退回后重新开放分区。
- 制单、录入与提交角色：`SUPPLY_CHAIN`、`SUPER_ADMIN`、`ADMIN`、`PURCHASER`。
- 审核与退回角色：`SUPPLY_CHAIN`、`SUPER_ADMIN`、`ADMIN`、`FINANCE`。
- **盘点审核角色按指令默认方向执行：SUPPLY_CHAIN/ADMIN/SUPER_ADMIN/FINANCE，允许 SUPPLY_CHAIN 审核；待用户复核。**
- 所有主单、分区、明细、用户、商品、仓库和调整单均按租户隔离；跨租户请求返回不存在或拒绝。

## 数据模型与并发控制

- 新增 `WarehouseStocktake`、`WarehouseStocktakeSection`、`WarehouseStocktakeItem`、`WarehouseStocktakeEntry`、`WarehouseStocktakeAdjustment`、`WarehouseStocktakeAdjustmentLine`。
- 迁移：`20260928005000_warehouse_stocktakes`，只采用向前兼容 migration，不使用 `db push`。
- 数据库部分唯一索引保证每个租户的同一仓库最多只有一张活动盘点单。
- 创建请求使用持久化 `requestKey` 幂等；同键同内容返回原单，同键不同内容返回 409。
- 分区保存、汇总提交和取消均使用 `rowVersion` CAS，负责人只能编辑自己的开放分区，避免旧页面覆盖或取消他人刚保存的结果。
- 建单时记录账面数量、价值和余额版本；审核时锁定主单与全部余额，再验证账面快照。盘点期间发生新出入库则整单拒绝审核，不覆盖最新库存。
- Serializable 事务冲突、活动盘点唯一冲突统一返回中文 409 提示。

## 库存过账与追溯

- 盘盈只为差额新增 adjustment 批次；盘亏只按 FEFO 从现有批次扣减差额，不清空或重建原有批次。
- 每个非零差异商品只生成一条稳定幂等的库存流水，来源为 `WarehouseStocktake`，并关联盘点明细与盘盈/盘亏调整明细。
- 同一张盘点单并发审核只允许一次真正过账；后续请求读取已确认结果。
- 活动预占高于实盘数量、可追溯批次不足或账面版本漂移时拒绝审核并整体回滚。
- 新来源已加入库存报表来源映射；现有盘点单、多人盘点单、盘盈单和盘亏单工作台均能读取总仓盘点结果，原有筛选、分页和导出框架保留。

## 页面与操作路径

- 新增 `/v2/supply-chain/stocktake/work`：选择仓库、日期、商品，建立分区并分配负责人；支持保存、分区提交、汇总提交、审核、退回、取消和查看调整单。
- 汇总和复盘继续复用 `/v2/supply-chain/stocktake/count/[id]`，通过 `source=warehouse` 读取总仓盘点详情与打印布局。
- 管理工作台新增“总仓多人盘点”入口，并为总仓记录附加来源参数。
- 退回与取消必须填写原因，使用 `ConfirmSheet` 输入确认层；本批未新增浏览器原生 prompt/confirm/alert。
- 移除库存工具栏中的“补记影子差异”入口；常规盘点从总仓盘点流程发起。
