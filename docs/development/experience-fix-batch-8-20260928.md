# 操作体验修复批次 8：旧入口收口、移动端与遗漏销号

日期：2026-09-28

范围：R-7、O-4，以及总清单中尚未单列批次的 F-4、F-6、F-8、N-2、O-5；本地实现与验证，未部署生产或 UAT。

## 本批改动

- 旧 `/login` 登录成功后按真实角色进入对应 v2 落地页，并同步 v1/v2 共用会话键；不再统一进入 v1 `/dashboard`。
- `/payments`、`/reconciliations`、`/schedules`、`/design-system` 四个无入口旧路由由 layout 返回 not found，历史页面源码保留，避免继续形成新书签或误用。
- finance 移动端与 PC 双实现不在本批强行归并，单独形成归并方案，要求先做字段、权限、状态和 API 对照，再从只读报表向写操作分阶段收敛。
- 单据审核、入库记录、总仓库存、批量入库、调拨和盘点复盘统一使用响应式数据表：桌面保持表格；小于 768px 时只挂载字段卡片，输入、动作和汇总均保留；打印复盘强制保持表格。
- 店长发起采购、去验收、提交后详情和送货单打印均保持在 `/v2/manager/purchase/**` 路由空间，复用同一采购实现，不再跳入厨师工作区导航语境。
- 供应商确认上游对账单后，在同一数据库事务内写入幂等财务通知；供应链页明确显示“已通知财务，等待锁定”，财务从消息中心可直达上游采购对账锁定页。
- 超级管理员老板首页直接提供 AI 经营助手和自动修复记录入口，减少三层深链。
- 供应商订单列表把伪快捷“接单/拒单”合并为“查看订单并处理”；真正动作仍在详情核对后执行。
- 独立差异页的按钮统一为“提出异议”和“确认短缺/差异 ¥金额”，与详情页及确认层口径一致。

## 安全与边界

- finance 双实现本批只输出方案，不删除、不迁移、不改权限。
- 响应式组件只改变展示形态，不复制表单状态、不改变请求和业务动作；手机和桌面任一时刻只挂载一套控件。
- 财务通知使用业务幂等键且只写系统消息；确认状态与通知原子提交，通知深链仍由财务页面权限守卫校验；对账单状态迁移和锁定权限不变。
- 店长别名路由受现有 manager 角色守卫保护，底层 API 权限不放宽。
