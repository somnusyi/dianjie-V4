# 财务报表 UI 审批稿

日期：2026-09-22。分支：DianJie_v1.1.0。来源：用户附件《财务报表.xlsx》Sheet1 A1:F35，只读提取，未修改附件。

## 当前阶段

用户明确先制作 UI 审批，确认后再连接后端和数据库。本次仅添加前端预览页面、示例数据及财务报表导航，没有新增财务 API、数据库模型或迁移。

地址：`http://127.0.0.1:3210/v2/supply-chain/finance-reports?report=group-profit`。沿用现有项目登录及主导航，工作台、订单中心、库存报表和账务查询继续保留。财务报表位于“核算与分析”，支持悬浮展开、移出 150ms 收起、点击和键盘焦点展开。

页面沿用用户已确认的库存报表 CSS：桌面默认筛选区约 43px，主表格占据剩余空间；窄屏自动换行。3 张表独立切换，顶部标签支持关闭，全部关闭后可重新选择。历史日期、客户、物品、单据等筛选及数值范围均作用于示例数据；还有排序、分页、列设置、紧凑行高、专注模式和示例 Excel 导出。

## 字段映射

| 报表 | 附件范围 | 保留字段 |
| --- | --- | --- |
| 集团毛利分析表 | 1–6 行 | 客户名称、配送中心、折后毛利、折后收入、出库成本 |
| 集团物品毛利分析表 | 7–21 行 | 仓库、客户名称、类别名称、物品名称、规格、单位、净销量、折后收入、出库成本、毛利率、折后收入均价、出库成本均价 |
| 集团毛利明细表 | 22–35 行 | 编码、名称、物品编码、规格型号、单据号、业务日期、出入库相关项、数量、成本、发货金额 |

删除项：第一张表不含配送渠道；第二张不含配送、统计类型、ABC分类；第三张不含订货机构、客户类型、渠道、统计类型。上述字段不会进入查询、列表或导出。

明细中的“编码、名称”与“物品编码”含义有歧义，已向用户询问；未收到回复前保留附件原标题，示例暂按客户编码/客户名称展示，正式接入前需确认。

## 示例数据与交互边界

48 条逐单逐物品示例记录，含 4 条返货入库，汇总形成 4 行客户毛利及 24 行物品毛利。明细、汇总来自同一组人工构造数据；净销量、收入及成本包含返货的负数冲减。折后毛利=收入−成本；均价和毛利率由汇总后的分子/分母计算，零分母为空。

成本只读，示例中不是由真实库存台账自动确认。正式接入后，应根据系统实际成本来源确定成本冻结时点、退货冲回、折扣/税额口径。不能以这些示例金额作为业务数据。

示例 Excel 保留每张表的全部所需字段和当前查询全部匹配行，不限于当前页，不随“列设置”临时隐藏字段。导出文件名称带“UI示例”，附“示例说明”工作表。页面始终标注示例数据。

## 本地登录入口修复

直接进入工作台后，未登录用户会转到 `/v2/login`。原登录页固定默认 `dianjie`，与本地供应链测试账号所属 `supply-chain-uat` 不一致。登录页现在支持 `NEXT_PUBLIC_PREVIEW_TENANT_SLUG` 默认租户配置，URL tenant 参数仍优先，未配置时维持原默认值。自定义租户显示实际租户名称，避免误标为正式环境。

本机忽略提交的 `apps/web/.env.local` 已设置 `NEXT_PUBLIC_PREVIEW_TENANT_SLUG=supply-chain-uat`。其他本地环境如需复现，应设置同一变量并重启 Web 服务；不包含账号密码变更。API 健康检查和本地账号登录接口均成功，浏览器现有会话可进入原工作台并看到两个报表入口。库存报表已接入本地后端，财务报表仍为 UI 示例。
