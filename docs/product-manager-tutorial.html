0这本教程怎么用

先搞清楚"懂"的标准，别用错力气。

目标不是记住全部规则，而是获得可靠判断力。这家公司有些业务口径至今未定，业务方自己也在讨论。

「懂」分四层

层级表现达成方式大致时间
L1 能复述流程知道收货后会派生账期、对账、凭证读这本教程3~5 天
L2 独立负责一块能独立处理"日报"这块业务的需求接一个小需求做一遍2~3 周
L3 判断跨环节影响要改报损金额算法，你立刻知道会连带影响应付、账期、凭证、对账四处踩坑 + 复盘1.5~2 个月
L4 拍板业务口径能回答"什么情况该冻结账期""用哪种应付口径"真实案例喂出来2~3 个月
体感 = L2 到 L3 之间它是被问题逼出来的，不是被文档灌出来的。先跟一笔真实交易走完全流程（第 7 节），不要从功能列表开始背。
学习的捷径遇到不清楚的业务规则，去问业务方，而不是从功能列表里猜。把每个"为什么这么算"记成一张口径清单，三个月后这就是别人没有的资产。

1先懂生意：一家餐馆每天在忙什么

所有复杂机制，都是为了让两个数字算得准、对得上、能追溯。

用食材换钱，赚的是差价；难的是食材会变质、数量不标准、而且一堆人参与其中。

① 卖了多少？（营收）

来自每天的营业。营业额、菜品销量，打烊后汇总出来。

② 花了多少？（成本）

主要是食材成本，占营业额的 30~40%。两者相减就是利润。

三流并行——复杂度全在"缝"上

flowchart LR
    A["物流
食材 供应商→门店→菜品"] --> D["对账与核算"]
    B["资金流
欠钱→付钱→记账"] --> D
    C["单据流
订单/送货单/发票/凭证"] --> D

货今天到，钱可能 30 天后付，发票可能更晚。货和钱速度不同，全靠对账缝在一起——这就是派生、对账、冻结这些机制的来源。

总厨管菜品配方、处理缺料、仲裁报损争议配方齐不齐、成本准不准

老板看报表、审批大额支出门店利润、成本率

2餐饮行业常识

配方、日报、成本率——餐饮成本核算的三块基石。

菜品 & 配方（BOM）

菜品是售卖单元（宫保鸡丁 38 元）。配方是这道菜需要什么料、各多少：鸡肉 300g、花生 50g、调料 15g。

毛重 & 损耗率

采购的鸡带骨，配方按毛重算，实际用量 ×(1+损耗率)。10% 损耗 → 300g 变 330g。

倒推消耗

核心魔法：不用每天称原料，只要知道卖了几份菜，就能算出用了多少食材。

日报——连接"卖"和"算消耗"的桥梁

每天打烊后整理两张表：营业统计（营业额、优惠、净收入）+ 菜品销售明细（每道菜卖了几份）。店长上报后要做三件事：

动作说明
记营业收入用净收入而非营业额（因为有打折、退菜）
记菜品销量每道菜卖了几份
按配方扣库存倒推食材消耗
餐饮铁律退菜不补回库存（菜已做，料已用）；赠品按配方扣减（它是正常销售，只是收入记为 0）；纸巾、蘸料这类明确标记为"不扣库存"的商品，不参与扣减。
关于数据来源在已经打通收银系统的餐饮软件里，这份日报数据是自动同步的；这里仍需店长每天上报。但无论手工还是自动，业务规则是一样的：先有销量，再用配方倒推消耗。

食材成本率（Food Cost %）

食材成本 ÷ 营业额 → 餐饮最核心指标，健康区间 30~40%

太高说明浪费/损耗/定价有问题，太低可能偷工减料。老板和财务报表里到处是这个指标。

3库存管理常识

餐馆不能实时称重，所以库存是"算"出来的。

预计库存公式

预计库存 = 上次盘点基准 + 后续已确认收货 − 做菜 / 人工 / 日报消耗 − 店内报损

定期做一次实物清点，重立可信基准。下次盘点重建基准，之前的误差一次性归零。所有页面和说明都必须带"预计"二字，不能说成实时库存。

三本账必须分开

flowchart TD
    A["门店预计库存
盘点基准 + 收货 − 消耗 − 报损"]
    B["供应商库存
供应商自己的货，独立流水"]
    C["总仓库存
批次 / 库位 / 台账 / 锁定"]
    A -.绝不能混算.-> B
    B -.绝不能混算.-> C
  • 门店的消耗绝不能改动供应商的库存数字——这是两本账。
  • 门店的安全库存线和供应商的安全库存线是两回事，不能混用。

单位换算

采购按"箱"、库存按"公斤"、下单要整箱起订。单位还没统一确认的商品，相关数量不参与库存计算——否则会把"箱"当"公斤"用。

移动加权平均成本

不同批次进价不同，库存金额按加权平均算。每次收货都会刷新平均成本——这就是"收货后要重算消耗成本"的原因。

4供应链与门店常识

餐饮供应链最特色的地方：三个量永远并列。

订购量

订 50kg

发货量

供应商发 48kg

实收量

门店收 48kg

三者差额就是到货差异（短缺、破损、错发），要走报损/索赔。供应商发货前可调发货量，门店收货时再确认实收量。

反直觉但正确的规则

规则为什么
原始订单不可覆盖订单是合同凭据。供应商可"申请改单"但必须门店批准，并保留原始单据，防止事后赖账
发货时调减不算报损"应到量"以供应商确认的发货量为准。发货环节协商调减，是正常履约
到货后少 2kg 才算报损实收小于应到，才是真正的短缺
送达不等于收货送达只是推进到"待验收"，收货必须门店人工确认，防止"货没到就自动收货、凭空入账"
首次发货即关闭履约未发余量直接关闭并通知"不补送"；要更多货得重新下单
短量报损按类型分组按"原因"分组会影响金额舍入边界，导致应付金额取决于操作员的措辞

到货差异的几种类型

短缺 破损 错发 店内报损

供应商可接受、拒绝；拒绝后由总厨仲裁。超过 24 小时不处理会自动同意（但逾期补报必须人工审批）。

供应商直送门店 vs 总仓采购

模式说明后果
供应商直送门店货物直接到店，当前主要模式产生应付、账期、发票
总仓采购总仓向外部供应商采购不产生对外部供应商的应付和账期，只留收货记录
PM 注意看到"总仓收货没生成账期"不要以为是问题，是业务设计如此。

5财务常识

从收货到付款的完整链条，以及最容易出错的两种应付口径。

完整链条

收货 → 账期 → 对账 → 发票 → 付款 → 资金流水 → 记账凭证
概念大白话
账期供应商赊账，比如"到货后 30 天付款"
应付账款欠供应商的钱，收货时就产生了
对账月底核对"我到底该付你多少"
发票供应商开的税务凭证，财务审核通过才能付款
记账凭证会计分录，记"钱从哪来到哪去"

复式记账（借 / 贷）

每笔钱都有借方和贷方，两边相等。收货时：

借：库存商品 1,056 元 贷：应付账款 1,056 元

付款时：

借：应付账款 1,056 元 贷：银行存款 1,056 元

含税 / 不含税——合规红线

绝对不能删用户已明确决定：税率与含税计算必须保留，不得删除或改口径，也不得自行给测试合同指定税率。这是合规红线。

含税

不含税额 = 金额 ÷ (1 + 税率)；税额 = 金额 − 不含税额

不含税

税额 = 不含税额 × 税率；总额 = 不含税额 + 税额

两种应付口径——最容易出错的地方

验收净额口径全额待索赔口径
收货时应付按实收金额（1,056）按订购全额挂账（1,100）
差异确认后不重复扣，只解冻账期扣差额 44 元 → 1,056
场景验收时就有差异验收后事后补报
结果相同，时机不同两种最终都付 1,056，但记账时机不同。选错口径就会重复扣钱或多付钱。

账期冻结

任何未结案的到货差异，都会把账期冻结起来——争议没结案，先别付钱，差异解决后才解冻。金额较大的账期（例如 2000 元以上）需要老板审批；银行的自动付款默认关闭。

其他财务模块速览

模块流程
月度成本核对门店 → 厨师长 → 供应商 → 财务，四方都确认才入账
备用金申请 → 审批 → 发放 → 报账 → 关账
工资Excel 上传 → 审批 → 发放（自动记账凭证）
资本支出店长申请 → 老板批 → 财务付（新店筹建、大型装修）
月结锁账关账后凭证不能再改；重开必须填原因

6五大业务流程

把前面四块知识串成五条业务流。

A 日报→配方→库存店长 / 总厨上报→核对→确认→补配方营业、销量、消耗、预计库存

E 门店履约厨师长/店长/供应商/总厨下单→接单→发货→送达→收货→完成配送单、收货单、报损、账期

流程 C、D 要点

D · 复核后才生效

单据在创建和审核阶段都不动库存，只有复核通过后才正式生效。盘点、调拨也一样——防止错误单据直接改账。

C · 防重复付款

账期自动付款与发票付款两条路径互斥，不能重复付。记账凭证是后补的，即使补记失败也不影响付款本身。

7真实案例串讲：到货少了 2kg

建立体感最快的一个场景，建议当新人培训第一课。

门店

合肥瑶海店

食材

鸡腿肉

订购 → 实收

50kg → 48kg

账期

到货后 30 天

1 · 下单

厨师长订 50kg

原始单据被记录下来，从这一刻起"订了 50kg"就钉死了。

状态：已提交
2 · 接单

供应商承诺供货

锁定的是供应商自己的库存，不是门店库存。

状态：已接单 + 锁定库存
3 · 发货

供应商发 50kg

发货时调减不算报损；首次发货即关闭履约，未发余量不补送。

状态：配送中
4 · 送达

货到了

只推进到待验收，不代表已收货——收货必须门店人工确认。

状态：待验收
5 · 收货

实收 48kg，少 2kg

应付按实收算：48 × 22 = 1,056 元。同时生成收货单和报损单。

收货单已确认 + 报损 2kg
6 · 派生

收货后自动生成

记账凭证（借库存/贷应付 1,056）+ 冻结账期 + 对账单。争议没结案，先别付钱。

7 · 差异

供应商确认少 2kg

按验收净额口径，不重复扣款，只解冻账期。订单完成。

报损确认 + 解冻账期
8 · 付款

30 天后财务付款

对账 → 审发票 → 付款 → 记资金流水 → 记账凭证。两条付款路径互斥，银行自动付款默认关闭。

这个案例教会你什么

机制防的风险
保留原始单据 + 改单需批准事后赖账、单方面改合同
锁定 / 移交 / 核销库存超卖、重复占用
三量并列生鲜短交扯皮
人工收货 + 唯一收货单重复收货、凭空入账
冻结账期争议未结就付错钱
两种应付口径重复扣款 / 少扣款
记账凭证 + 复式记账账实不符
系统不是在"记录数据"，而是在替餐馆和供应商，把每一笔可能扯皮的交易，变成所有人都认账、出问题能倒查的原始凭证。

8产品经理的工作边界与决策清单

PM 最大的价值不是画图，而是把业务口径问清楚、写明白。

遇到需求先问：业务规则 or 操作体验？

类型谁拍板例子
操作体验PM 可以定，看效率和易用性页面加搜索、列表分页、按钮文案
业务口径必须找业务方拍板应付按实收还是全额、什么情况冻结账期、税率口径
口径红线（不能碰）
  • 税率与含税计算必须保留，不得删除或改口径
  • 原始订货单的订购量、单价不可无痕覆盖
  • 供应商库存与门店库存分账，不能混算
  • 门店库存必须显示"预计"二字，不冒充实时库存
  • 退菜不补库存；标记为不扣库存的商品不参与扣减
  • 总仓来源收货不产生对外部供应商的应付

尚待业务确认的事项（别自作主张）

事项当前临时规则PM 能做什么
已确认入库更正尚未定稿不覆盖原记录，先明确规则
补送与报损关系补送要计成本和库存，不设免费补送等业务确认规则后再考虑
负库存默认不应静默允许先告警、阻止

自测 5 题（答得上来就有体感了）

1. 为什么送达之后不自动收货？

参考答案

防止"货没到→自动送达→自动收货→凭空入账"，收货事实必须门店人工确认。

2. 报损确认后应付金额变不变？（要答出分两种口径）

参考答案

验收净额口径不变（只解冻账期）；全额待索赔口径要扣差额。

3. 为什么供应商改单必须门店批准？

参考答案

订单是合同凭据，防止供应商单方面改账；原始数量和单价不可无痕覆盖。

4. 一张收货单会带来什么？其中哪一项失败不影响收货本身？

参考答案

带来记账凭证、账期、对账单；凭证是后补的，补记失败只留提醒，不影响收货。

5. 税率字段能不能删？为什么？

参考答案

不能删——税率与含税计算是已有业务口径，属合规红线，用户已明确决定必须保留。

学习建议不要从一堆功能列表开始背。先理解一笔完整交易从下单到付款是怎么走的，再去抠某个环节。遇到想不通的规则，问业务方，而不是从界面上猜。
