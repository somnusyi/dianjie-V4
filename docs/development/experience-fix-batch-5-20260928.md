# 操作体验修复批次 5：原生弹窗迁移

日期：2026-09-28

范围：问题 O-2；本地实现与验证，未部署生产或 UAT。

## 改动范围

本批只处理问题盘点 O-2 明确列出的页面，不顺带改动清单外的历史页面：

- 供应链采购：采购单审核发送、退货驳回/取消/审核出库/供应商实收、收货冲销、差异办结。
- 供应商上游：接单、发车、对账异议、确认对账。
- 总仓库存：单位换算核验、门店订货库存策略切换。
- 库存导入：设置期初基准、写入每日流水、批量确认同名映射、撤销导入。
- 门店库存：安全库存与建议补货目标改为共享确认层中的结构化双字段编辑。
- 财务初审：批量通过、单笔通过、填写理由驳回。
- 厨师长链：店内报损、验收单、收货后补报异常、门店收货中的上传、校验、提交成功/失败反馈。

## 统一交互

- 需要确认的业务动作统一使用 `ConfirmSheet/useConfirmSheet`，不再调用浏览器 `window.confirm`。
- 驳回、取消、冲销和对账异议等必填理由使用确认层输入框，空值不可提交；库存导入撤销额外校验至少 2 个字。
- 门店安全库存需要同时填写两个数值，仍复用 `ConfirmSheet`，在确认层正文中提供安全库存和建议补货目标输入，不再连续弹出两个原生 prompt。
- 厨师长操作中的裸 `alert` 改为页面内 `role="alert"` / `role="status"` 提示；错误出现后聚焦提示，上传成功和验收单发送成功给出明确下一步。
- 所有原有 API、状态流转、幂等键、库存/金额含义保持不变；本批只替换交互承载方式和错误呈现。

## 防重复与失败处理

- 共享确认层在请求期间进入忙碌状态并阻止重复确认。
- 页面原有 `working/submitting/saving` 状态继续生效。
- API 失败时确认层保留错误或页面显示可聚焦错误，不伪装成功。
- 厨师长验收单发送成功后按钮变为“已发送”，防止重复提交，并提供“返回采购列表”下一步。

## 测试

- 新增 O-2 契约测试，逐页扫描目标文件，禁止 `alert/prompt/confirm` 原生调用；确认页必须使用共享 `ConfirmSheet`，厨师长页必须使用无障碍页内反馈。
- 更新库存与库存导入交互测试，使其实际点击确认层的取消/确认按钮。
- 新增/补充厨师长四页测试，覆盖大视频、上传失败、缺少必填、收货失败、成功下一步和防重复发送。
- 聚焦验证：10 个测试文件、45 项测试通过。
- 最终验证：API 124 个测试文件、1251 项测试通过；Web 80 个测试文件、927 项测试通过；API/Web 类型检查、API 构建和 Web 生产构建通过。
