0这本教程怎么用

先搞清楚"懂"的标准，别用错力气。

目标不是记住全部规则，而是获得可靠判断力。这套系统有些业务口径至今未定，业务方自己也在讨论。

「懂」分四层

层级表现达成方式大致时间
L1 能复述流程知道收货后会派生账期、对账、凭证读这本教程3~5 天
L2 独立负责一块能独立处理"日报导入"的需求接一个小需求做一遍2~3 周
L3 判断跨模块影响要改报损金额算法，你立刻知道会连带影响应付、账期、凭证、对账四处踩坑 + 复盘1.5~2 个月
L4 拍板业务口径能回答"什么情况该冻结账期""用哪种应付口径"真实案例喂出来2~3 个月
体感 = L2 到 L3 之间它是被问题逼出来的，不是被文档灌出来的。先跟一笔真实单据走完全流程（第 7 节），不要从功能列表开始背。

1先懂生意：一家餐馆每天在忙什么

所有复杂机制，都是为了让两个数字算得准、对得上、能追溯。

用食材换钱，赚的是差价；难的是食材会变质、数量不标准、而且一堆人参与其中。

① 卖了多少？（营收）

来自收银 / POS。每天打烊后产生营业额、菜品销量。

② 花了多少？（成本）

主要是食材成本，占营业额的 30~40%。两者相减就是利润。

三流并行——复杂度全在"缝"上

flowchart LR
    A["物流
食材 供应商→门店→菜品"] --> D["对账与核算"]
    B["资金流
欠钱→付钱→记凭证"] --> D
    C["票据流
订单/送货单/发票/凭证"] --> D

货今天到，钱可能 30 天后付，发票可能更晚。货和钱速度不同，全靠对账缝在一起——这就是派生、对账、冻结机制的来源。

角色地图

角色在餐馆里干什么在系统里关心什么
厨师长 / 店长看库存、下单、收货、报损、上传日报预计库存够不够、货到得对不对
总厨管菜品配方、处理缺料、仲裁报损争议BOM 齐不齐、成本准不准
供应商接单、送货、开发票订单改没改、什么时候付款
内部供应链管总仓采购、配送、商品主数据合同价、验收、月结
财务对账、审发票、付款、记账应付金额、账期、凭证
老板看报表、审批大额支出门店利润、成本率

2餐饮行业常识

BOM、日报、成本率——餐饮成本核算的三块基石。

菜品 & BOM

菜品是售卖单元（宫保鸡丁 38 元）。BOM 是配方：鸡肉 300g、花生 50g、调料 15g。

毛重 & 损耗率

采购的鸡带骨，BOM 按毛重算，实际用量 ×(1+损耗率)。10% 损耗 → 300g 变 330g。

倒推消耗

核心魔法：不用每天称原料，只要知道卖了几份菜，就能算出用了多少食材。

日报——连接"卖"和"算消耗"的桥梁

每天打烊后收银系统导出两张表：综合营业统计（营业额、优惠、净收入）+ 菜品销售明细（每道菜卖了几份）。店长上传后系统做三件事：

动作说明
记营业收入用净收入而非营业额（因为打折、退菜）
记菜品销量每道菜卖了几份
按 BOM 扣库存倒推食材消耗
餐饮铁律退菜不补回库存（菜已做，料已用）；赠品按 BOM 扣减（它是正常销售行，显式收入为 0）；百家蘸料、纸巾标记为 EXCLUDE 不扣库存。
关于美团真正的美团到店 SaaS 里，日报数据是 POS 通过 API 自动同步的。本系统用"手工上传双表"，是 POS 集成未打通时的临时替代——代码里有 MEITUAN_ENABLED 开关但生产没开。

食材成本率（Food Cost %）

食材成本 ÷ 营业额 → 餐饮最核心指标，健康区间 30~40%

太高说明浪费/损耗/定价有问题，太低可能偷工减料。老板和财务报表里到处是这个指标。

3库存管理常识

餐馆不能实时称重，所以库存是"算"出来的。

预计库存公式

预计库存 = 上次盘点基准 + 后续已确认收货 − BOM / 人工 / 日报消耗 − 店内报损

定期实物清点一次，重立可信基准（系统里叫 InventorySnapshot）。下次盘点重建基准，之前的误差一次性归零。页面和接口必须带"预计"二字。

三本账必须分开

flowchart TD
    A["门店预计库存
盘点基准 + 收货 − 消耗 − 报损"]
    B["供应商库存
供应商自己的货，独立流水"]
    C["总仓库存
批次 / 库位 / 台账 / 预占"]
    A -.绝不能混算.-> B
    B -.绝不能混算.-> C
  • 门店消耗绝不能改供应商 Product.stock——这是两本账。
  • 门店安全库存用 StoreInventoryPolicy，不能复用 Product.minStock（那是供应商口径）。

单位换算

采购按"箱"、库存按"kg"、下单整箱起订。单位没换算或状态 PENDING，相关行会被排除在库存滚动之外——否则会把"箱"当"kg"用。

移动加权平均成本

不同批次进价不同，库存金额按加权平均算。每次收货都会刷新平均成本——这就是"收货后要重估消耗成本"的原因。

4供应链与门店常识

餐饮供应链最特色的地方：三个量永远并列。

订购量

订 50kg

实发量

供应商发 48kg

实收量

门店收 48kg

三者差额就是到货差异（短缺、破损、错发），要走报损/索赔。供应商发货前可调实发量，门店收货时再确认实收量。

反直觉但正确的规则

规则为什么
原始订单不可覆盖订单是合同凭据。供应商可"申请改单"但必须门店批准，系统保留不可变快照防赖账
发货时调减不算报损"应到量"以 shippedQty 为准。发货环节协商调减是正常履约
到货后少 2kg 才算报损实收 < 应到，才是真正的短缺
自动送达 ≠ 自动收货24h 只解锁状态，收货必须门店人工确认，防止"货没到→自动收货→幽灵入账"
首次发货即关闭履约未发余量直接关闭并通知"不补送"；要更多货得重新下单
短量报损按 kind 分组按"原因"分组会影响两位小数舍入边界，导致应付金额取决于操作员措辞

到货差异的几种类型

短缺 ARRIVAL_SHORTAGE 破损 ARRIVAL_DAMAGE 错发 WRONG_ITEM 店内报损 INTERNAL_WASTE

供应商可接受、拒绝；拒绝后由总厨仲裁。逾期 24h 不处理会自动同意（但逾期补报必须人工审批）。

供应商直送门店 vs 总仓采购

模式说明财务后果
供应商直送门店货物直接到店，当前主要模式产生应付、账期、发票
总仓采购（HEADQ_WAREHOUSE）总仓向外部供应商采购不建外部应付凭证和账期，只留收货记录
PM 注意看到"总仓收货没生成账期"不要以为是 bug，是设计如此。

5财务常识

从收货到付款的完整链条，以及最容易出错的两种应付口径。

完整链条

收货 → 账期 → 对账 → 发票 → 付款 → 资金流水 → 凭证
概念大白话
账期供应商赊账，比如"到货后 30 天付款"
应付账款欠供应商的钱，收货时就产生了
对账月底核对"我到底该付你多少"
发票供应商开的税务凭证，财务审核通过才能付款
凭证会计分录，记"钱从哪来到哪去"

复式记账（借 / 贷）

每笔钱都有借方和贷方，两边相等。收货时：

借：库存商品 1,056 元 贷：应付账款 1,056 元

付款时：

借：应付账款 1,056 元 贷：银行存款 1,056 元

含税 / 不含税——合规红线

绝对不能删用户已明确决定：税率与含税计算必须保留，不得删除或改口径，也不得自行给测试合同指定税率。这是合规红线。

含税

不含税额 = 金额 ÷ (1 + 税率)；税额 = 金额 − 不含税额

不含税

税额 = 不含税额 × 税率；总额 = 不含税额 + 税额

两种应付口径——最容易出错的地方

NET_AT_RECEIPT（验收净额）GROSS_PENDING_CLAIM（全额待索赔）
收货时应付按实收金额（1,056）按订购全额挂账（1,100）
差异确认后不重复扣，只解冻账期扣差额 44 元 → 1,056
场景验收时就有差异验收后事后补报
结果相同，时机不同两种最终都付 1,056，但记账时机不同。选错口径就会重复扣钱或多付钱。

账期冻结（ON_HOLD）

任何未结案的到货差异，都会把账期置为 ON_HOLD——争议没结案，先别付钱。差异解决后才解冻。金额 > 2000 元需老板审批；招行 CMB 自动付款默认关闭。

其他财务模块速览

模块流程
月度成本核对门店 → 厨师长 → 供应商 → 财务，四方都确认才入账
备用金申请 → 审批 → 发放 → 报账 → 关账

流程 D & C 要点

D · 复审才生效

制单和审核都不动库存，只有「复审」才真正过账。盘点、调拨也一样——审核后还要复审，防止错误单据直接改账。

C · 防重付

账期自动付款与发票付款两条路径互斥，不能重复付。凭证在事务外补建，失败只留警告不回滚付款。

7真实案例串讲：到货少了 2kg

建立体感最快的一个场景，建议当新人培训第一课。

门店

合肥瑶海店

食材

鸡腿肉

订购 → 实收

50kg → 48kg

账期

到货后 30 天

1 · 下单

厨师长订 50kg

写入不可变快照，从这一刻起"订了 50kg"钉死。

状态：SUBMITTED + 快照哈希
2 · 接单

供应商承诺供货

动的是供应商库存账（预占 50kg），不是门店账。

状态：CONFIRMED + 预占
3 · 发货

供应商发 50kg

发货时调减不算报损；首次发货即关闭履约，未发余量不补送。

状态：DELIVERING
4 · 送达

货到了

只解锁，不自动收货——收货事实必须门店人工确认。

状态：PENDING_CONFIRM
5 · 收货

实收 48kg，少 2kg

应付按实收算：48 × 22 = 1,056 元。原子生成收货单 + 报损单。

Receipt CONFIRMED + 报损 2kg
6 · 派生

收货后自动生成

凭证（借库存/贷应付 1,056）+ 账期 ON_HOLD + 对账单。争议没结案，先别付钱。

7 · 差异

供应商确认少 2kg

NET_AT_RECEIPT 不重复扣款，只解冻账期。订单 COMPLETED。

报损 APPROVED + 解冻
8 · 付款

30 天后财务付款

对账 → 审发票 → 付款 → 资金流水 → 凭证。防重付互斥，CMB 默认关闭。

这个案例教会你什么

机制防的风险
不可变快照 + 哈希事后赖账
预占 / 转交 / 核销超卖、重复占用
三量并列生鲜短交扯皮
原子收货 + 唯一约束重复收货、幽灵入账
账期冻结争议未结就付错钱
两种应付口径重复扣款 / 少扣款
凭证 + 复式记账账实不符
系统不是在"记录数据"，而是在替餐馆和供应商，把每一笔可能扯皮的交易，变成所有人都认账、出问题能倒查的原始凭证。

8产品经理的工作边界与决策清单

PM 最大的价值不是画图，而是把业务口径问清楚、写明白。

遇到需求先问：系统机制 or 业务口径？

类型谁拍板例子
系统机制PM 可以定，看技术/体验页面加搜索、列表分页、按钮文案
业务口径必须找业务方拍板应付按实收还是全额、什么情况冻结账期、税率口径
口径红线（不能碰）
  • 税率与含税计算必须保留，不得删除或改口径
  • 原始订货单的订购量、单价不可无痕覆盖
  • 供应商库存与门店库存分账，不能混算
  • 门店库存必须显示"预计"二字，不冒充实时实物库存
  • 退菜不补库存；EXCLUDE 菜品不扣库存
  • 总仓来源收货不建外部应付

尚待业务确认的事项（别自作主张）

事项当前临时规则PM 能做什么
已确认入库更正尚未定稿不覆盖原记录，先做方案和测试
补送与报损关系补送要计成本和库存，不设免费补送等业务确认状态机后再实现

自测 5 题（答得上来就有体感了）

1. 为什么 24h 自动送达后不自动收货？

参考答案

防止"货没到→自动送达→自动收货→幽灵入账"，收货事实必须门店人工确认。

2. 报损确认后应付金额变不变？（要答出分两种口径）

参考答案

NET_AT_RECEIPT 不变（只解冻账期）；GROSS_PENDING_CLAIM 要扣差额。

3. 为什么供应商改单必须门店批准？

参考答案

订单是合同凭据，防止供应商单方面改账；原始数量/单价不可无痕覆盖。

4. 一张收货单派生了什么？哪个派生失败不会让收货回滚？

参考答案

派生凭证、账期、对账单；凭证在事务外补建，失败只留警告，不回滚收货。

5. 税率字段能不能删？为什么？

参考答案

不能删——税率与含税计算是 1.3.1/1.3.2 已有口径，属合规红线，用户已明确决定必须保留。
