# 会议改动：采购退货

## 业务口径

- 采购退货是供应链内部单据，不要求上游供应商拥有登录账号。
- 只能选择已经过账且未冲销的采购收货明细；采购单位、库存换算和结算单价沿用原收货冻结值。
- 保存草稿、提交审核均不改变库存。
- 审核通过时从采购方总仓扣减库存，并为每一行生成唯一的 `PURCHASE_RETURN` 总仓流水。
- 供应商实际收到退货后单独登记 `RECEIVED`；该动作不再改变采购方库存，也不写入门店履约供应商的 `SupplierStock`。
- 累计退货数量不得超过原合格收货数量。待审核、已审核出库和供应商已收货均占用可退数量；驳回、取消和草稿不占用。
- 退货结算金额使用原收货采购单价；库存成本使用审批出库当时的总仓移动平均成本，两者分别保存，不相互替代。

## 状态与库存影响

| 状态 | 操作 | 库存影响 |
| --- | --- | --- |
| `DRAFT` | 内部创建 | 无 |
| `PENDING_APPROVAL` | 提交审核 | 无；占用原收货可退数量 |
| `APPROVED` | 审核通过 | 采购方总仓出库一次 |
| `RECEIVED` | 登记供应商实际收货 | 无新增库存动作 |
| `REJECTED` | 审核驳回 | 无；释放可退数量 |
| `CANCELLED` | 草稿/待审核取消 | 无；释放可退数量 |

## 数据与接口

- 数据表：`upstream_purchase_returns`、`upstream_purchase_return_lines`、`upstream_purchase_return_events`。
- 迁移：`20260928001000_upstream_purchase_returns`、`20260928002000_upstream_purchase_return_supplier_tenant_fk`。
- API 前缀：`/api/upstream/purchase-returns`。
- 页面：`/v2/supply-chain/procurement` 的“采购退货”页签。
- 库存与单据：`purchase-return` 已由占位页改为真实数据源；已审核单据按实际出库日期显示，草稿、待审核、驳回和取消单据按创建日期显示，避免日期筛选将其静默隐藏。

## 安全与并发

- 所有查询和写入均带租户边界。
- 退货单到供应商的外键同时包含 `tenantId`，数据库会拒绝跨租户供应商引用。
- 提交和审批均锁定原收货明细，重新确认原收货仍为已过账且未冲销，并核对累计可退数量。
- 原收货已存在待审核、已审核或已收货的采购退货时，不允许直接冲销原收货。
- 审批使用 Serializable 事务、退货单行锁、库存余额锁和稳定幂等键。
- 并发重复审批只允许一条出库流水，其余请求返回幂等重放。
- 可退库存按“物理库存－门店已预留库存”计算；退货不得挪用已预留库存。
- 任一行可用库存不足时整张退货单审批回滚，不产生部分出库。
