真实 PostgreSQL 测试发现：盘点日期是 DATE 字段，使用上海零点对应的 UTC 时间筛选会落入前一天，导致当天盘点漏查。已将 DATE 筛选按日期字面值的 UTC 零点构造上下界；时间戳字段继续按上海业务日计算。新增集成用例覆盖目标日命中、前后相邻日排除。另为两个纯重定向入口补充防伪造页面测试的精确白名单，未放宽实际业务页面规则。

## 复验入口

常规自动化入口为 `pnpm --filter @dianjie/api test`、`pnpm --filter @dianjie/api test:integration` 和 `pnpm --filter @dianjie/web test`。运行前应使用项目要求的 Node 20 / pnpm 10.32.1，并给集成测试提供专用测试数据库。

新增 `apps/api/scripts/verify-local-management.ts` 用于对运行中的服务执行真实 HTTP 业务验证。要求本机地址、数据库名称以 `_test` 结尾、`PREVIEW_MODE=true`，并预先完成迁移及 UAT 种子；从 `apps/api` 目录执行 `pnpm exec tsx scripts/verify-local-management.ts`。可用 `LOCAL_VERIFY_API_URL` 和 `LOCAL_VERIFY_WEB_URL` 指定本机端口。该脚本会在隔离库创建并保留测试单据，每次运行库存净增加 25kg / 250 元，不应当作只读健康检查运行。

本机已准备好忽略目录中的 `tmp/run-local.mjs`，用于安全加载本地配置；加入 `--integration` 参数使用第二个隔离库。例如在仓库根目录执行：

```sh
npm exec --yes --package=node@20 --package=pnpm@10.32.1 -- node tmp/run-local.mjs pnpm --filter @dianjie/api exec tsx scripts/verify-local-management.ts
```

该本机辅助文件不随仓库提交。HTTP 验证摘要在 `tmp/live-api-verification.json`，测试日志分别为 `tmp/api-unit-tests.log`、`tmp/all-integration-tests.log`、`tmp/web-final-tests.log`，不含需提交的应用代码。
