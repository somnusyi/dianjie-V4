## 连接与交付

1. 完成 ACR 访问凭证的设置或核对。新密码必须由用户本人设置；不把网站密码、NAS 密码或服务器 SSH 凭据当作 ACR 密码。
2. 通过 Docker 的标准输入登录，秘密不放在命令参数、版本文件、源码、镜像、聊天或 QA 日志。持久保存凭据须明确授权；在此之前不写个人或服务器的默认 Docker 登录配置。
3. 本地按 `linux/amd64` 构建并验证适用于阿里云测试环境的应用镜像。原华为候选是 ARM64 且带测试租户/存储限定，不能仅改标签就当成阿里云候选。
4. 对选定候选确定版本和源码范围，推送两个仓库，记录 registry 返回的摘要，在控制台验证真实版本存在。不得上传 `.env`、真实数据库、测试密码或密钥目录。
5. ECS 选用实际可达的同地域 VPC 地址，按已核对的摘要拉取并检查架构。公网/VPC 两端必须验证内容一致，不能因名称相似推断成功。
6. 运行镜像在 ECS 本地仍占空间。先完成磁盘/内存、数据库与附件路径、旧凭据兼容、备份和回退验证，再切换测试版。ACR 不是数据库或附件的备份位置。

当前两个候选镜像均已上传，原 ECS 按相同摘要拉取成功，amd64/node 检查通过；在原 ECS 临时运行两容器，只读连接 UAT，登录页 200，前端代理 API 健康正常。摘要和完整阶段见 `docs/qa/evidence/ALIYUN-ACR-20261027/candidate-status.json`。本地和服务端本轮临时仓库凭据已清除，临时探针容器和密钥也已删除。
