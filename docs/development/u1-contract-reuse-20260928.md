# U-1 合同复用与下单直通（2026-09-28）

## 现状核实

- 现有 `UpstreamSupplierContract.purchaseOrders` 是一对多关系，`UpstreamPurchaseOrder.contractId` 指向合同；一份长期框架合同本来就能支撑多张采购单。
- 合同与采购单的业务关系不改。为避免快速建合同超时重试误生成 V2 草稿，只新增合同创建的持久化幂等键和请求指纹。

## 实现

- 新建采购单先选供应商：
  - 该供应商只有一份 `ACTIVE` 合同时自动带出，不显示重复选择器；
  - 有多份 `ACTIVE` 合同时才显示合同选择器；
  - 没有 `ACTIVE` 合同时，在当前采购单面板直接显示“快速建合同”。
- 快速合同默认带出当前供应商、框架合同名称、当日生效日，以及商品供货关系的 `quotedUnitPrice`。
- 合同草稿创建后保留在采购单上下文，成功横幅可一键启用；启用使用 `ConfirmSheet`。
- 合同列表原生 `window.confirm` 已替换为 `ConfirmSheet`，并去掉与可点合同标题重复的“查看合同内容”按钮。
- 供应商无可采购货源时，提示可直达商品管理维护供货关系与价格。
- 快速切换供应商时，只接受最后一次货源请求的响应，旧请求不能覆盖当前供应商价格。
- 合同创建同一幂等键、同一内容直接回放原合同；同一键但内容不同返回 409，并发重试也不会多建草稿。
- 网页、上游 E2E 和本地管理验证脚本均传入稳定的合同幂等键，不保留会回归 400 的旧调用。

## 业务默认方向

- 按修复指令默认：唯一生效合同无需人工再选；多合同不代替用户决策；无合同时允许就地快速建草稿，但仍需人工确认启用。
- 快速合同的价格来自当前供货关系，可在保存前修改；不自动将草稿绕过确认直接生效。

## 验证

- Web 聚焦测试：23 项通过（包含唯一/多合同/无合同快速创建、幂等键与乱序货源响应）。
- API 幂等指纹与路由聚焦测试：6 项通过，覆盖持久重放、同键异内容 409、P2002/P2034 并发回读。
- Web 全量回归：74 个文件 / 915 项通过。
- API 全量回归：124 个文件 / 1251 项通过。
- Web/API 类型检查、Prisma schema 校验和 `git diff --check`：通过。
- 独立只读复审：无 P0/P1，同意提交；大范围格式化噪音记为非阻断 P2。
