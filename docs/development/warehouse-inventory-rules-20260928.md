# 仓库库存规则实现记录（2026-09-28）

## 业务范围

- 库存上下限按“租户 + 仓库 + 商品”独立配置，数量统一采用商品的库存基准单位。
- 库存预警与配置读取同一条规则，状态为：缺货、低于下限、正常、高于上限、阈值未配置、单位待确认。
- 呆滞天数按商品持久化，默认 30 天；报表查询允许临时覆盖，但不会改写持久配置。
- 呆滞库存仅提醒，不自动移库。
- 旧 `Product.minStock` 只在商品从未建立仓库规则且单位换算已核验时兼容读取；建立后再停用规则不会恢复旧值。

## 数据与审计

- `WarehouseInventoryPolicy` 保存库存单位快照、上下限、呆滞天数、启停状态和 CAS 版本。
- `WarehouseInventoryPolicyEvent` 保存结构化前后值、操作人快照、requestId 和请求指纹。
- 更新采用 `rowVersion` 乐观锁；同 requestId、同内容可安全重放，不同内容返回 409。
- 数据库约束保证上下限非负、下限不高于上限、呆滞天数为 1–36500、版本非负。
- 规则只能软停用，商品、仓库和规则不能级联删除审计事件。

## 页面流程

- 入口：库存管理 → 库存上下限。
- 支持切换仓库、搜索商品、逐行编辑及保存、跳转库存预警和呆滞品报表。
- 旧安全库存显示“兼容生效 / 待迁移”，首次保存前明确确认迁移。
- 单位变化需二次确认；停用需危险确认并说明不会恢复旧安全库存。
- 保存一行不会覆盖其他草稿；切仓、查询、分页、菜单、报表深链及浏览器离开均保护未保存修改。
- CAS 冲突只刷新冲突商品，其他未保存草稿保留。
- 移动端按商品卡片展示，与桌面端使用同一 API 和字段语义。
