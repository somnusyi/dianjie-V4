# 1.3.3-hotfix.1 · 门店登录恢复

正式版和测试版 API 已更新；页面仍显示业务版本 1.3.3，数据库与前端未更改。

企业微信实际从 `https://njdianjie.com` 进入，1.3.3 的正式 API 浏览器会话允许名单漏了这个域名，登录和企微授权在查账号前被拒绝。已把该域名补入正式运行配置。另发现密码登录路由的旧限流按服务端所见 IP 每分钟 10 次计算；反向代理使不同门店共用该额度，现改为同一账号每分钟 20 次，手机号和邮箱只以哈希值作为限流键。企业微信 OAuth 走独立路由，本次事故日志中该路由出现的是 403，没有 429；因此不能把密码登录限流当成企微批量失败的原因。

本次 API 镜像基于 1.3.3 固定镜像，仅覆盖登录路由和新增的限流辅助模块。正式与测试使用同一热修镜像 `sha256:edb7309e0152a2cb1e14b291ee033ee8f47f4299df0b78706b747920bc45c20f`；原镜像 `sha256:4ec8f3be22738c52b06e24aad53abf7e5939a0812c6da30367606dae7419a516` 保留。没有导入账号、订单或其他数据，也没有变更审批、库存与财务逻辑。

验证：测试版同一合成不存在账号的前 20 次请求均完成账号校验，第 21 次返回 429，另一个账号仍完成账号校验；正式企业微信授权接口恢复 200，合成不存在账号的登录返回正常 401，两个 API 的健康与数据库状态均正常。其他受影响门店的端到端登录仍需由门店实际操作确认。

补充核对（北京时间 2026-11-06）：企微授权在 16:08、16:09 仍有成功请求，16:15 起集中返回 403；修复后 17:46 出现江阴八佰伴店的企微登录审计成功、授权回调和会话续期成功。宜悦城与雨山龙湖在上午有企微登录成功审计。门店反馈图中“早上能登、后来不能登”与时间变化吻合，但访问日志没有门店名称，不能将每个 403 直接归属到某家门店。百家湖、万达茂、城北万象城当前均无已启用门店账号、各有待处理申请，属独立的账号开通问题；仙林金鹰无已启用账号或待处理申请。其余门店仍需按具体人员核对。

回退：两站原 API 容器分别保留为 `dianjie-uat-api-before-rate-20261106`、`dianjie-production-api-before-rate-20261106`，正式版修改前的会话配置另有私有备份。若新限流代码异常，恢复同为 1.3.3 的前一 API 容器并保留已修正的企业微信域名；不要恢复旧业务数据库或降回 1.3.2。启动命令及部署清单已记录热修镜像，避免再次启用旧限流。
