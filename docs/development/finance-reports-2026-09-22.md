# 财务报表后端与数据库联调

日期：2026-09-22；分支：DianJie_v1.1.0。用户已批准 UI，授权接入后端与本地数据库。仅本地修改和验证，未推送、未部署。

## 页面与接口

原页面 `/v2/supply-chain/finance-reports` 的三个 report 值 `group-profit`、`item-profit`、`profit-detail` 保持不变。复用审批通过的紧凑查询区、大表格、悬浮菜单、可关闭标签及列设置。删除预览假数据，默认日期改为上海时间当月首日至今天；查询失败显示错误，不回退示例数据。异步请求序号隔离旧响应，避免切换或连续查询串表。

新增 `GET /api/supply-chain/finance-reports/:report`，查询参数包括 start/end、customer/center、keyword、warehouse/category/unit、document/source、ranges(JSON)、page/pageSize、sort/direction；`export=1` 返回 filename、fileBase64、total。页面与导出共用同一只读投影，导出全部匹配记录，保留全部附件字段；列隐藏仅影响显示。

列表返回 rows、total、page、columns、options、note、warnings。服务端验证真实日历日期、起止顺序、有限数值范围及分页。读取采用 RepeatableRead 事务；来源数据超过 20,000 条明确要求缩小日期范围，不静默截断。

权限：SUPPLY_CHAIN 复用已有 finance.read；ADMIN、SUPER_ADMIN、FINANCE 可读。供应商、门店等其他角色禁止读取及导出。所有来源查询、关联、筛选选项均限定当前租户。原有 `/api/finance/reports` 门店经营报表保持独立。

## 数据来源与计算口径

复用现有 PostgreSQL 表，不新增 schema 或迁移：

- `delivery_orders` / `delivery_order_items`：总部供应商 HEADQ_WAREHOUSE 配送单、客户门店、冻结商品字段和成交单价。
- `warehouse_ledger_movements`：DeliveryOrder 的 ORDER_OUTBOUND 实际出库数量、金额、库存单位与生效时间。
- 三类实际 REVERSAL：ReceiptRejectionReversal（返货入库）、LossClaimReversal（到货短缺冲回）、DeliveryOrderShipCancel（配送撤销/减量）。通过 sourceLineId 关联原出库，原单可在查询期间之前。单据撤销后仍保留历史出库和冲回，不按当前状态删历史。
- `stores`、`warehouses`：客户编号/名称和仓库。无独立配送中心模型，本次配送中心取实际出库仓库。

收入 = 业务原单位数量 × 配送行冻结成交单价，按正负方向入账；使用订单记录的成交价，不自行推断额外折扣或税额。成本 = 出库台账 valueDelta 的相反数；不以当前商品价格或当前库存均价回算历史。数量为库存单位，与成本一致；均价按库存单位净销量计算。商品名称、分类、规格采用配送行快照，历史缺失展示空值，不用当前商品覆盖。客户与仓库名称采用当前主数据。

汇总毛利 = 净收入 − 净成本；毛利率 = 毛利 / 净收入；均价 = 净金额 / 净数量。先用 Decimal 汇总再计算比率，零分母显示空值。物品汇总按客户、仓库、商品、库存单位、规格、分类分组，不将不同计量单位相加。数值范围作用于汇总后的值。

已发货但没有出库成本流水的历史/OFF 配送，按当前配送行实发金额列出，成本为空并有提示；该组成本、毛利及成本均价不计算。缺少可核对配送关联的流水不计入，返回数量警告。未记成本行不是历史不可变财务凭证，应先补齐业务事实再对账。

报表范围为总部配送经营毛利，不含门店收银收入、采购退货、门店间调拨及未关联配送单的美团导入数据。报表查询本身不修改库存、订单、价格或财务凭证。

明细“编码、名称”继续按客户编码/客户名称，另有“物品编码”。本轮已向用户询问歧义，尚未收到回答，按此前预览解释暂定；没有更改附件标题。

## 验证结果

- API 与 Web TypeScript 检查通过。
- PostgreSQL 集成测试 5 组：身份/角色/跨租户隔离、上海日期边界、跨期退回、撤销保留历史、冻结价格/商品快照、汇总及筛选、分页、三张 Excel 逐单元格一致性、错误参数、缺成本传播。
- 计算边界单测 4 组：Decimal 精度、加权均价、完全退回零分母、缺成本、不混客户/仓库/单位、非法参数。
- Web 新增 2 个测试：API 权限失败不显示示例、连续查询不接受旧响应。现有供应链导航 10 个测试通过。
- 本地真实 HTTP 链路：管理员创建测试订货 → 供应链接单 → 发货 → 配送明细数量由 2 改为 1，全部通过既有业务 API。三张报表直接 API 与 Next 代理一致；FINANCE 返回 200，供应商返回 403。
- 浏览器核对三张表、客户筛选、冲回类型筛选；导出下载文件已逐项核对数量 -1、成本 -10、发货金额 -3.5。浏览器未捕获错误。工具下载事件等待超时，但实际文件落入 Downloads 并已核验，未将事件超时误判为业务失败。
