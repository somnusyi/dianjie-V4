# 账号限流修复候选（2026-11-09）

## 范围与原因

- 原全站 `200 次/分钟` 按 `request.ip` 计数；API 位于同一台 Nginx 后，未启用代理信任，所有用户被识别为 `127.0.0.1`，共享 200 次。
- 另有 14 个单独限流入口沿用 IP 计数，其中 6 个已登录入口、8 个公开入口。登录入口已有独立的账号限流，不在这 14 个之内。
- 修复后，全站普通已登录接口按租户和账号分别计数，仍为 `200 次/分钟/账号`。单独限流的 6 个已登录入口也按账号计数，并保留原次数和时间窗。刷新会话用验签后的刷新令牌认定账号；无效令牌按真实客户端地址计数。
- 8 个公开入口尚无账号身份，按 Nginx 看到的真实客户端地址分别计数，保留原次数和时间窗。登录接口仍按租户和填写的账号计数。
- 只信任本机 Nginx 的转发地址；线上生产、测试容器均使用 host 网络，API 仅监听本机地址。健康检查不占业务额度。

## 验证

- `apps/api` TypeScript `tsc --noEmit` 通过。
- 限流测试 7/7 通过，覆盖同代理不同账号、单独入口额度、真实客户端地址、防伪造转发链、刷新令牌和原登录账号限制。
- 只读核对生产和测试容器的 Docker 网络模式为 `host`；未对线上业务数据进行写入或压力请求。

## 发布与回退

- 候选仅含 API 限流配置、刷新入口和测试；没有数据库结构或数据迁移，也不改网页。
- 尚未发布到测试版或正式版。发布时先固定候选镜像摘要、在测试版验证跨账号并发与登录续期，再更新正式版并观察 429、401 和健康检查。
- 若异常，切回现用 API 镜像 `sha256:edb7309e0152a2cb1e14b291ee033ee8f47f4299df0b78706b747920bc45c20f`，不回滚数据库。
