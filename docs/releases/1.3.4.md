# 1.3.4

本版修正并补齐供应链总仓“盘点单／多人盘点单”。发布顺序为本地隔离验证、测试环境、正式环境；不导入本地账号、测试数据或模拟单据。

## 本轮变化

- 盘点范围只包含供应链正式商品：保留正式菌菇，排除门店库存镜像、BOM 临时商品和本地配方镜像。
- 单人盘点和多人盘点补齐机构、仓库、物品、状态、差异、类型、方案、复审、生成状态、打印状态及备注筛选，不增加系统中不存在的辅助单位字段。
- 指定商品可只选一个正式菌菇保存；无余额商品会建立零余额台账，不再要求把全部分类勾完。
- 多人盘点保持独立子单，审核后按同日同仓汇总生成正式盘点单；单人／正式盘点和多人子单继续分开展示。
- 创建人或管理员可修改表头、增删排序商品、刷新单位、提交、取消和删除；供应链审核角色负责审核／驳回／复审／反审核；财务只读，采购和门店角色不可写总仓盘点。
- 旧版盘点的原复核人和复核时间继续显示为审核信息；迁移不回写旧数量、金额、状态或旧审核字段。
- 保留旧 API 切换兼容的明细来源默认值，避免迁移与容器切换之间出现写入失败。

## 数据与回退边界

本版新增 9 项盘点结构迁移，不包含 `INSERT`、`UPDATE`、`DELETE`、`MERGE`、`TRUNCATE` 或本地数据库导入。旧业务字段升级前后哈希校验必须一致。上线后若已产生 1.3.4 新盘点事实，不得恢复旧数据库或直接降回 1.3.3；应重新部署已验证的 1.3.4 镜像或前向热修。

## 本地验证

- API 单元回归 1817 项通过、7 项跳过；Web 单元回归 1724 项通过、2 项跳过。
- 盘点真实数据库集成回归 52 项通过；从 1.3.3 全量结构升级到 1.3.4 后，旧盘点业务字段哈希保持一致。
- API、Web 类型检查和生产构建通过，健康接口报告 1.3.4。
- 鼠标验收通过：单人指定盘点和多人盘点子单均可只选择一个正式菌菇并保存；页面未出现辅助单位字段；管理员可管理他人单，财务只读，采购和店长不能进入总仓盘点。
